## 先分清两件事：F6 不是产线

| | 需求 F6（端口工装） | 产线测试（这份文档要的） |
|---|---|---|
| 受众 | 一个硬件工程师 | 产线操作员 + 质量部门 |
| 形态 | 一块板、手动点、看数 | 12 工站、外部仪器、自动判定 |
| 判定 | **人看**（`porttool.h` 头注释明说「Nothing here judges anything」） | 逐项限值自动 Pass/Fail |
| 上位机 | 浏览器面板 | CLI 序列 + 报告归档 |

**共用的是同一份 DUT 固件和同一份 `pt.*` 协议，上位机侧是两套不同的消费者。** 这一点 [DECISIONS.md 第 8 条](DECISIONS.md) 已经预留了：一个 exe，双击起面板 / 带子命令走产线。

范围上五条已拍板，**不要重开**：[DECISIONS.md 第 19–23 条](DECISIONS.md) —— 工装板归硬件做、SN/标签/过站/装箱不做只留接口、产线烧写走 SWD 整片重烧、**判定一律在上位机**、**五个通信口的判据逐口定**。

## 被测对象是整机，不是单板

2026-09-07 与硬件工程师确认：**四块板（Bridge / Upper Deck / Lower Deck / Junction Link）装成整机一起测，各个端口的测试内容保持不变。**

**后果**：「多板型 / 按板型选用例」这个维度**不存在**，配置项不需要拆到板型粒度。仓里本来也没有这个概念 —— 板子之间的差异靠运行时 `pt.caps` 自报，主机侧没有、也不需要一份「这块板应该有什么」的期望表。

⚠️ **但焊接变体仍然存在，且固件读不回来**：AI 档位（AIN1 电压 / AIN2 电流）、AO 的 JP3/JP4、CAN 终端电阻 JP7。这些是**产线要保证一致、软件无法自检**的东西 —— 见 [FIXTURE-INTERFACE.md](FIXTURE-INTERFACE.md) 第一节第 3 条。

## 架构契合度：「通用框架 + 标准数据化」这个模型对上了多少

用户 2026-09-07 提出的参考架构：**上位机做通用框架、留足配置项、测试用例和合格标准单独写成数据、框架靠标准判合格。**

| 要素 | 契合 | 事实 |
|---|---|---|
| **设计意图** | ✅ **完全一致** | [PORTTOOL-FLOW.md](PORTTOOL-FLOW.md) C.3 原话就是这个模型：判定和序列全在上位机，固件只报原始采样，改判据不用重烧固件 |
| **端口拓扑数据化** | ✅ **已做到** | 端口形状（名字 / 端子 / 通道数 / 参数名 / 回环类型）是结构体数据，`pt.caps` 自描述；上位机**零硬编码**（`$TOOL/internal/ptproto/caps.go` 刻意拒绝保留端口清单） |
| 参数约束数据化 | ✅ **2026-09-08 做到** | caps 多一行 `limits=`，值从 `*_apply()` 用的同一批宏生成。上位机据此**离线判方案文件里的参数值**，不用再抄第二份 |
| 一次性动作数据化 | ✅ **2026-09-08 做到** | caps 多了 `kind=run` 行 + `runs=`，八个 `pt.run` 目标由固件自报。**这是「方案文件能离线校验」成立的最后一块** —— 之前方案里打错一个目标名，只能在产线上、板子面前才发现 |
| **判据 / 限值数据化** | ✅ **产线这条路做到了** | 方案文件（JSON）里每一步自带 `checks`，算子在 `internal/ptcheck`，面板和产线序列共用。⚠️ **老用例那批判据仍然散在五种形态**：markdown 散文、Python 字面串匹配、Go 常量 + `if`、C `check()` 参数、编译期 `static_assert` —— 那是另一件事，没有排期 |
| 用例序列数据化 | ✅ **产线这条路做到了** | `internal/ptplan` 读方案文件，`internal/ptseq` 按序执行并管六个通用字段。两份真方案在 `$TOOL/TestCase/plans/`（`bench-smoke.json`、`station6-poweron.json`），都由测试拿假板子真跑一遍 |
| 执行框架 | ✅ **产线这条路有了第三个，而且是数据驱动的** | `internal/ptseq`：判据在方案文件里，不在二进制里。⚠️ **老的两个仍然并存、互不相通**：Go 侧 `testCase{id,title,destructive,manual,run}` 注册表（`$TOOL/TestCase/main.go`，**判据编译进二进制**）；Python 侧 `selfcheck` 的 `CATALOG` + `run_step`（**只看子进程退出码**，自己不含判据） |
| 结构化报告 | ✅ **产线这条路做到了** | `internal/ptreport` 逐项原始值出 CSV/JSON，**判据本身也进报告**，重试不覆盖原失败。⚠️ `selfcheck.py`（老用例那条路）仍然只有染色日志 + 退出码 |
| 多板型 / 变体 | — | 不需要，见上一节 |

**结论（2026-09-08 修正）：意图 100 % 对上，骨架齐了，「标准」这一层已经落成代码。**「判据 / 限值数据化」那一行的 ❌ 是 2026-09-07 的状态；四个包 `ptplan` / `ptseq` / `ptcheck` / `ptreport` + 方案文件已经补上，工站 6 的方案是 `$TOOL/TestCase/plans/station6-poweron.json`。仍然散在五种形态里的是**老用例**（P/H/C 那批）的判据，不是产线这条路。

那一层要长成什么样，用户 2026-09-07 给了参考架构（另一个项目的产线工装截图），读解与格式定义在 [PRODUCTION-FRAMEWORK.md](PRODUCTION-FRAMEWORK.md)。

这不是设计跑偏 —— 期一、期二只做了 C.3 三支里的「手动」那一支，产线和自动化那两支正好是需要标准数据化的两支。

⚠️ **这个缺口仍然在老用例那条路上咬人。** 同一个限值存两份、无一致性检查：TCP 空闲踢线的 `60s / +15s` 在 `$TOOL/TestCase/TEST-CASES.md` 的判据散文里和 `$TOOL/TestCase/tcp_session.go` 的常量里各一份，而用例 P7 的一致性检查**只对用例号不对数字**。产线这条路刻意不重犯：端口参数的限值由固件的 `limits=` 自报，`pt.run` 目标由 `runs=` 自报，方案文件里对不上就在 `porttool validate` 里当场报出来。

## 测试内容对不上的三类

⚠️ **这一节说的不是「有没有」，是「测的不是同一件事」** —— 比上面那张表更容易漏。

### 1 · 文档要「速率」，代码测「通不通」

文档对五个通信口用同一句话（「传文件 + 读速率判定」），而**大部分口测的仍然是「通不通」**：以太网 2026-09-08 起有了真速率（`eth` 会话的 `kbps`，见上表）；USB 还是零；CAN 固定 500 kbit/s 收发帧；RS485 是回环计数 `seq/rx/miss/junk`；KNX 是位时序 + 边沿直方图。

处理办法已定，见 [DECISIONS.md 第 23 条](DECISIONS.md)。

### 2 · 文档要「实测值」，代码给「算出来的期望值」

**这条最容易在产线上出事，因为数看着是真的。**

| 项 | 代码实际给的 |
|---|---|
| **AO 电流** | `µA` 是 `mv × 10000 / RSET` **算出来的**（`../../TestCase/common/port_dac.c`，`RSET=1024`），**不是量出来的**。板上无回读通道 |
| **AI 端子值** | 档位换算**固件里根本没有**，只报引脚上的 raw/mV。系数在 [HARDWARE-FACTS.md](HARDWARE-FACTS.md)，刻意推给上位机（`porttool_ain.c` 有明文声明） |
| 高边输出 / 继电器 | 只驱动，电压电流全靠外部读；继电器连触点回读都没有 |

### 3 · 文档要「判定」，代码明确拒绝判定

`../../TestCase/porttool/porttool.h` 的头注释写着 *"Nothing here judges anything"*。**这是立场不是遗漏** —— `../../TestCase/DAC/dac_test.h` 还写了理由：跳线焊没焊固件读不回来，所以给不出判据。

按 [DECISIONS.md 第 22 条](DECISIONS.md)，这个立场保留并推广到全部端口。

### 内容一致、不用改的

DI 八路读回、DO 八路 + 软件 PWM、继电器逐路驱动、温度两路（老镜像连合法带都有了，`../../TestCase/ADC/adc_test.c`）、SD 读写 + CRC 比对、SDRAM（容量常量正好 64 MiB，走线 / 地址 / 保持三段齐全）。

分类沿用测试规程 3.6 的模块划分，加上散落在各工站的非 DUT 项。

⚠️ **「现状」一列的判据是「产线软件能不能自动判定这一项」**，不是「有没有人能手动测出来」。后者会把一堆只能人肉看串口的东西记成已完成。

记号：✅ 有且可判 · 🔨 有一半 · ❌ 没有

### A · Junction Link（电源与导轨）

| 名称 | 内容 | 现状 |
|---|---|---|
| 待机 / 最大功耗 | 关掉全部功能测待机，测试中记录最大值；上位机从**外部电压电流模块的寄存器**读 | ❌ |
| 3.3 V / 5 V / 5V_EXT 电压 | 同上。判据「暂定值 ±5 %」 | ❌ 固件里唯一的电源数是 `vdda=`（VREFINT 推的），[porttool_ain.c](../../TestCase/porttool/porttool_ain.c) |
| DIN 导轨连接器信号回环 | DUT 自测回环，结果经 RS232 报出 | ❌ |

### B · Bridge（主控）

| 名称 | 内容 | 现状 |
|---|---|---|
| SWD 连接 / 烧录 | 上位机经**外部 JLINK** 读 DUT 状态判定 | ❌ `TestCase/` 全仓没有 SWD 相关代码 |
| SDRAM 压力自测 | 经 RS232 让 DUT 自测。判据「识别 64 MB + 零错误」 | ✅ **2026-09-08 齐了**：`pt.run sdram.probe`（容量 + 两条总线）、`sdram.sweep`（**整片 64 MiB 四花样**，报 `mismatches` 与 `first_bad`），保持力由 `sdram` 会话跑。全部报原始值，主机判。⚠️ `sweep` 要几十秒 |
| 以太网通信 | DUT 与固定网络设备传文件，报速率 | ✅ **2026-09-08 齐了**：`eth` 会话是板上一个 TCP server（`porttool_eth.c`），三个模式 —— `echo` 闭环计数、`sink` 收大文件、`source` 发大文件，每帧报 `rx_bytes` / `tx_bytes` / `kbps`。`eth.link`（MDIO 探 PHY）仍在同一行上。⚠️ **kbps 是板子自己算的窗口速率，不是判据** —— 多少算合格由上位机定。**真板子上还没跑过** |
| USB 通信 | 同上，固定 USB 设备 | ✅ **2026-09-08 齐了**：`usb` 会话把 CDC 管道当数据通道用（`porttool_usb.c`），四个模式 —— `echo` 闭环计数、`sink` 收大文件、`source` 发大文件、`info` 只报枚举状态。帧里 `state=`（枚举到哪一步）、`enum=`（枚举变了几次）、`busy=`（主机不读了，和线断了是两回事）。⚠️ **板子是 Device 不是 Host**，对端是产线 PC 打开那个虚拟串口。**真板子上还没跑过** |
| SD 读写压力 | DUT 自测并报结果 | ✅ **2026-09-08 齐了**：`pt.probe` 之外加了 `pt.run sd.integrity passes=64` —— **64 轮** 4 KiB 写/读/CRC，报 `passes` `passed` `bytes_total` `elapsed_ms` `first_bad_pass`。⚠️ **判据必须同时看 `passes` 和 `passed`**：中途卡死时 `passes` 跟着变小，只看 `passed` 会把「跑一轮就放弃」判成通过 |
| RTC 读 + 写校准值 + 回读 | — | 🔨 **读有了**：`pt.run rtc.read`（自己按需 `MX_RTC_Init()`，报 `init/clk/date/time`）。**写校准没有** —— 备份域里住着 iap_auth 的 nonce 计数器，写那里的测试等于能把安全计数器回滚。⚠️ 而且 `rtc.c:74` 选的是 **LSI 不是 LSE**，精度先天不够，谈校准之前要先定这个 |
| 指示灯 | 上位机弹窗，人工看、人工选 | ✅ **两半都有了**：`pt.run led.blink` 闪 `PE2` 六次（`MX_GPIO_Init()` 不配这个脚，目标自己配），回复里是 `observed=unknown`（没有回读）；判定由 `UserConfirm` 步骤问人。工站 6 方案里就是这两步连着 |
| 老化模式 | 全项通过后进老化模式：全负载开、DUT 自监控、异常灯告警、自计时 2–4 h 到点自动退回测试模式 | ✅ **面板的「持续」模式**：勾多个端口、选 1/2/3/4 小时或一直跑，一次启动。⚠️ **计时在上位机，不在板子**（[DECISIONS.md](DECISIONS.md) 第 37 条）；异常灯也由上位机判完再点（`pt.led fault=1`），因为板子不判任何东西。**上位机死了那一类情况由看门狗兜底**：`pt.hold` 每 2 秒续一次，6 秒没续上板子自己关输出并点灯。原来那个 `soak` 端口和 `plans/soak-2h.json` 已删 |

### G · 产线流程与追溯 —— **不做，只留接口**

SN 分配与防重、标签打印（板级 / 整机 / 箱标）、逐站过站记录、四板绑定、装箱入库、人工判定入口、LOG 管理与查询。

软件侧只需要两个口：**SN 从外部读入**、**结构化报告往外部写出**。理由见 [DECISIONS.md 第 20 条](DECISIONS.md)。

## 还要问硬件工程师的两件事

**两条的原文和背景住在 [FIXTURE-INTERFACE.md](FIXTURE-INTERFACE.md) 第五节** —— 那份是要交到硬件工程师手上的，问题归那里。本节只记它们各自挡着什么。

### Q1 · DI 那句措辞矛盾 → 只影响工装板设计

**不挡软件。** 跟接口清单一起澄清。

### Q2 · AI / AO 的 0.1 % 是硬指标吗 → **挡着 E 组整块**

产线指南 3.10 要求「写补偿值再重测」，2.6 要求校准数据与整机 SN 绑定。而规格书自己的备注说这个指标需要全温校准，且主流是 0.3 % / 0.6 % 级。**指标松到 0.3 %，逐板校准很可能整件事不需要做，E 组消失。**

**若 0.1 % 是硬的**，则「系数存哪」要定 —— 产线用 SWD 整片重烧会把它抹掉：

| 路 | 怎么做 | 代价 / 风险 |
|---|---|---|
| A · 独立扇区，重烧不抹 | 划一页 flash 专放校准，JLINK 烧写限定地址范围不碰它；用户固件从固定地址读 | 要在 Arduino core 侧加读取代码 → **地址与结构成为新的跨仓镜像项**；烧写脚本一旦整片擦除就静默丢校准 |
| B · 最后一次烧写时写进参数区 | 产线只记录系数，出厂前上位机在烧用户固件时一并写入 | 不改 core，但要「按板 SN 定制烧写」，且系数存放回到外部系统 —— 和「MES 不做」冲突 |
| C · 不做校准 | AI/AO 只判「在范围内」，不做补偿 | 零代价，但 0.1 % 达不到 |

**这三条是取舍，等用户定，不写进 [DECISIONS.md](DECISIONS.md)。**
