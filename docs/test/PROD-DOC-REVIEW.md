出处：`Hardware/OPENPLC生产测试指导文件_V0.1_20260904.docx`，涉及 **3.6**（工站 6 PCBA 上电测试）和 **3.10**（工站 10 成品测试）的软件需求。

## 一、要改的四条

| # | 文档位置 | 问题 | 建议 |

## 二、24 项软件需求的三分

**16 项能自动判，6 项只能人工，2 项不做。**

### 自证，已经在跑（14 项）

| 文档测试项 | 怎么测 | 判据字段 |
|---|---|---|
| SDRAM 压力 | `sdram.probe` + `sdram.sweep` | `size` `ready` `databus` `addrbus` / `patterns` `mismatches` |
| SDRAM 保持 | `sdram` 会话 | `cycles` `failed` |
| SDRAM 读回校验 | `sdram.crc` | `ready` `offset` `bytes` |
| SD 读写压力 | `sd.probe` `sd.integrity`（`passes=` 决定几轮）`sd.speed` | `fs` `identical` `passes` `passed` |
| SD 检测脚 | `sd` 会话 | `detected` |
| 以太网 | `eth.link` + `eth` 会话 | `found` `link` `speed` / `conn` `miss` |
| USB | `usb` 会话 | `state` `enum` `miss` |
| RTC 读 | `rtc.read` | `clk` |
| 温度 | `temp` 会话 | `ok` `vdda` `ch1[1]` `ch2[1]` |
| RS232 | `rs232` 会话 | `miss` `rxlines` |
| RS485 引脚级 | `rs485.pins` | `checked` `busy` `follows` |
| RS485 链路 | `rs485` 会话 | `miss` `junk` `overrun` |
| CAN | `can` 会话 `mode=extloop` —— 过收发器和隔离器，不需要第二个节点 | `miss` `rx_frames` `junk` `lec` |
| KNX | `knx` 会话 `mode=frames` | `bus` `vcc` `chars` `bad` |

### 自证，但要一根跳线（2 项）

| 文档测试项 | 怎么测 | ⚠️ |
|---|---|---|
| DI 通断 | 外部把八路拉高，`din` 读回位图 | 判据 `v eq 0xFF`。**激励从哪来是工位的事**，上位机不指定夹具 |
| AI | `AOUT → 已知阻值电阻 → AIN` | AOUT 是**电流**输出，中间必须串电阻；两头共用同一个 VREFBUF，**验线性不验绝对精度**。⚠️ 两个脚现在彻底悬空，等焊 JP5/JP6/JP8/JP9（[AIN-JUMPER-REQUEST.md](AIN-JUMPER-REQUEST.md)） |

### 只能人工（6 项）

**板子没有任何采样通路，软件怎么写都拿不到数。** ⚠️ **这六项要在文档里明确标成人工测量** —— 否则产线会等一个永远不会出现的自动判定。

| 文档测试项 | 为什么 |
|---|---|
| 待机功耗、最高功耗 | 24 V 上没有分压采样进 MCU |
| 3.3V / 5V / 5V_EXT 电压 | 同上 |
| 高边输出的电压电流 | VNQ5160K-E 的电流 sense 没有回到 MCU |
| 继电器触点的电压电流 | 触点是干接点，走到端子 `B01-B12`，板上无回读 |
| AO 输出电流 | `D14 → 表 → Analog GND` 串量。⚠️ 期望值取决于 JP3/JP4 焊没焊 |
| 指示灯 | PE2 无回读，只能人看 |

### 不做（2 项）

| 文档测试项 | 依据 |
|---|---|
| Hutschienenverbinder 扩展口环回 | 没有能插 J4 的陪测板；`PH13/PH14` 和控制口共用 UART4 |
| 一切「测试软件读 PC 外接电压电流模块 / 信号发生仪 / 陪测板」 | 没有实物和型号，写了也验不了 |

## 三、要让产线知道的两件事

**1. 高边输出和继电器的自动判据是「回显」，坏板子照样过。**

`high-side-out` 判 `ch1 eq 100`、`relays` 判 `ch1 eq 1` —— 那两个数是刚下发的命令值，不是回读。输出级整个坏掉（VNQ5160K-E 不导通、继电器线圈断）这两步照样通过，它们证明的只是「命令被接受了」。

补法是**跳线**，不是陪测板：高边输出接到 DI 读回；继电器触点串 24 V 接到 DI。⚠️ **接法要硬件工程师确认**（触点额定、DI 门限）。在那之前，文档里要写明这两项的自动判定管不着输出级本身。

**2. SN / 标签 / 过站 / 装箱不在「功能测试软件」里。** 文档已经把它列成独立的「系统管控软件」条目，建议在功能测试软件那一条下明确写不含这些，避免归属含糊。

## 四、文档里还没有数的

**所有限值都是 TBD** —— 功耗、模拟精度、速率门限。判据文件的形状已经有了（`$TOOL/TestCase/plans/*.json` 每一步自带 `checks`），缺的是数。**这些数由硬件/质量填进方案文件**，不写进代码（[DECISIONS.md 44](../design/DECISIONS.md)）。
