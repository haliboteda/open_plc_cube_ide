# 端口联调计划 —— 一个端口一个端口打通

**这份文件回答一件事：每个端口现在卡在哪，要谁做什么才能让它在真板子上过。**

判据一律以 `$TOOL/TestCase/plans/station6-poweron.json` 为准，实测结论记在 [PORTTOOL-FIRST-BENCH.md](PORTTOOL-FIRST-BENCH.md)。工装镜像是独立固件，不为 flash 里的任何东西让路（[../design/DECISIONS.md 第 33 条](../design/DECISIONS.md)）。

**「打通」的定义**：那个端口在**真板子**上跑 station6 时转 PASS，不是模拟板上过。

## 第 0 批：一个程序打通三个端口（不等任何人）

**`eth` / `usb` / `rs485` 三个端口的判据都只差一件事：一个对端。** 它们的形状是同一个 —— 板子发一个数，对端原样送回（`loop=link`，[../design/DECISIONS.md 第 18 条](../design/DECISIONS.md)）。所以是**一个程序**，不是三个。

| | 内容 |
|---|---|
| **做什么** | `$TOOL` 里一个 `porttool answer` 子命令：同时在 TCP、板子枚举的 CDC 口、和一个指定串口上当应答器，收到什么原样送回 |
| **为什么值得先做** | 一次让三个端口从 FAIL 转 PASS，而且它是**产线本来就必须有的东西**（[../design/PRODUCTION-TEST-GAP.md](../design/PRODUCTION-TEST-GAP.md) 的 Golden endpoint 那一行早就写着「产线 PC 要跑一个应答器」） |
| **判据** | 真板子跑 station6，`eth` `usb` `rs485` 三行转 PASS；`miss` 全程 0，`conn=1` |
| **谁做** | 我。⚠️ `rs485` 那一路还要你把适配器接到 C09/C10（见第 1 批） |
| **机制已经有了** | `Tool` 步骤类型（起外部进程、判输出或退出码）在 `internal/ptseq` 里已实现，所以方案文件能直接起它 |

## 第 1 批：你顺手就能做的两件（各一分钟）

# 🍍 请插一张 FAT32 格式的 microSD 卡

插进 Bridge 板的 **J6**。⚠️ **必须是 FAT32，不能是 exFAT** —— 工程里 `_FS_EXFAT=0`，exFAT 卡会挂载失败。

# 🍍 请把 USB-RS485 适配器接到 C09 / C10

A 接 **C09**，B 接 **C10**（就是之前记的 COM16 那个适配器）。

做完这两件，`sd` 的三步和 `rs485` 就都有了打通的条件。

## 第 2 批：纯固件，我做

### 2.1 编码器 1–4 → `din mode=quad` ✅ 代码完成 2026-09-10

⚠️ **不做成独立端口。** 八路数字输入的信号名就是 `DIN1_PC6-Enc1a` … `DIN8_PI6-Enc4b`（[../design/HARDWARE-FACTS.md](../design/HARDWARE-FACTS.md)）—— **同一组引脚兼作四组编码器的 A/B 相**。做成两个端口会让人以为可以同时测，物理上不行。

| | 内容 |
|---|---|
| **做了什么** | `din` 会话有了 `mode=level`（原来的行为，默认）和 `mode=quad`。编码器 n 用通道 2n-1（A 相）和 2n（B 相），所以编码器 1 是 DI1/DI2 |
| **帧** | `!din t=… v=0x00 mode=quad g1=124 d1=1 g2=0 d2=0 g3=0 d3=0 g4=0 d4=0 err=0`。`g` 是带符号计数，`d` 是最后一次看到的方向（+1/-1，没动过是 0），`err` 是**两相同时翻转**的次数 |
| **为什么 quad 模式不报 `ch<n>=`** | 八个通道对加上四组计数最长 226 字节，`PORTTOOL_LINE_MAX` 是 192，会被静默截断成解析不了的帧。`v=` 本来就是全部八个引脚，什么都没少 |
| **`err` 为什么单列** | 两相同时翻转推不出方向 —— 要么转太快本轮采样漏了一步，要么有一相没接。计数在涨而 `err` 跟着涨，那个计数就不能信，所以报出来而不是替它选一个方向 |
| **归零** | 重启会话。没有「清零」参数：能在跑的过程中清掉的计数，报告读不回去 |
| **在哪测的** | H4（`$TOOL/TestCase/host/porttool_caps/build.py` 的「quadrature decoding」）直接驱动 A/B 状态，判正反向、四组互不串扰、非法跳变进 `err`。**不需要板子** |
| **判据** | 转动编码器，对应那一组的计数单调变化、方向跟着转向翻转；不动时计数不动 |
| **激励** | ⚠️ **仍然缺。** 需要一个能转的编码器，或者那根八芯线从 `dout` 接过来 —— `pt.set dout duty=…` 可以按 00→01→11→10 的次序推出 A/B 相序列，整个激励都能从 PC 驱动。没有激励时它和 `din` 一样是「如实失败」（`v=0x00`，四组计数全 0） |

### 2.2 RTC 写校准

读已经有了。两个前置要先处理：备份域里住着 `iap_auth` 的 nonce 计数器（不能被清）；`rtc.c:74` 选的是 **LSI 不是 LSE**，精度不够谈校准。

## 第 3 批：要激励源，光有代码不够

| 端口 | 需要什么 | 现在的失败是对的 |
|---|---|---|
| `din` | 八路输入的激励。最省事的是那根八芯线把 `dout` 接到 `din`（面板已有「DO → DI 对照」视图，判据是**矩阵对角**，与极性无关） | `v=0x00` |
| `ain` | D12/D13 的信号源 | 读数落在悬空带 |

⚠️ **`ain` 的百分比限值现在写不出来。** JP1–JP9 档位不定，端子到引脚的换算系数就是未知的 —— **没有分母**。现在两份方案都只能判「不是悬空」。

## 第 4 批：扩展口 —— 要先定方案，不是写代码

`PH13/PH14` 接到扩展口 JunctionLink J4-11/J4-12，**也是 UART4**，和 RS232 端子上的控制台共用同一个外设。同一个 UART 只有一个句柄槽，最后一次 `begin()` 赢。

**所以扩展口的 TTL 串口和工装自己的命令通道不能同时存在。** 三条路，代价都不一样：

| | 做法 | 代价 |
|---|---|---|
| A | 把控制通道搬到 USB CDC，UART4 让给扩展口 | 改的是工装的命脉，风险最高；但 USB 会话已经证明 CDC 通道可用 |
| B | 做成交权目标（`pt.handover expansion`），交权后不需要命令通道 | 结果只能人看，且要复位才能回来。⚠️ TX↔RX 自环时控制台的每个字符会被自己收到，命令解析会自己喂自己 —— 要先处理这个 |
| C | 不测扩展口串口，只测它上面的其他信号 | 覆盖不全，但零风险 |

**等你定。** 在定之前这一项不动。

## 顺序与理由

```
第 0 批（应答器）          ← 先做：一个程序换三个端口，且产线本来就要
   ↓
第 1 批（插卡 + 接线）      ← 你顺手，和第 0 批并行
   ↓
第 2 批（编码器 ✅ + RTC 写） ← 纯固件，不等人
   ↓
第 3 批（激励源）           ← 八芯线接上就能测 din
   ↓
第 4 批（扩展口）           ← 等你定方案
   ↓
第 5 批（仪器 / 工装板）    ← 等外部
```

**给工程师的初版应该在第 0 批和第 1 批做完之后发** —— 那时 19 个端口里 16 个在真板子上过，剩下的三个（`din` `ain` + 编码器）缺的是激励而不是代码，说得清楚。
