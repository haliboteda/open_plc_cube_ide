## ★ 过期的结论是一类没人在测的缺陷

**2026-08-17 核对 `RELEASE-NOTES.md`，四条 known-issue 里有四条已经不对了：**

| 它写的 | 实际 |
|---|---|
| bootloader 报版本 `0.1.2` | 当天已改成 `0.1.3` |
| `[BOOT]` banner **到不了** RS232 端子 | 到得了 —— 靠电荷泵余电，`millis=12` 实测 |
| 乱码字节"三个候选，都未确认" | 已排除两个，根因确定是电荷泵塌陷 |
| 备份域误报"根因仍未查明" | 当天已定位（DR2 跨仓撞车）并修复 |

**那份是对外的，升级风险全靠它兜着。** 一条过期的 known-issue 会让读的人去查一个已经不存在的问题，**比没有这一条更糟**。

**`P1` 只能抓住版本号形态的过期**（它就是这么发现第一条的）。其余三条是靠人工逐条核对翻出来的，**没有任何自动化能覆盖**。

## 一条相关的教训：长期 SKIP 等于状态未知

**H2 长期报 SKIP**（本机没有 host C 编译器）。装上 MinGW-w64 之后第一次真跑，**它根本编不过**：

```
iap_auth.c:139: error: 'RTC_BKP_DR3' undeclared
```

原因是 2026-08-17 修 DR2 撞车时把 VBAT witness 从 `DR2` 搬到了 `DR3`，而 `host/bootloader_unit/stubs/rtc.h` 只定义到 `DR2`，**没人跟着改**。

**也就是说 H2 从那次修复起就是坏的，而 SKIP 让它看起来只是"没测"。**

文档里原来写的是"静默跳过的检查会被读成通过，那比没有这个检查更糟" —— **实际情况比这还糟一层：它掩盖的不是覆盖缺失，是这个检查本身已经不能运行了。**

已修（stub 补齐 `DR0`–`DR7`，`s_bkp[8]` 本来就撑得住），11 条断言全过。

> **教训：一个长期 SKIP 的检查，要当成"状态未知"，不能当成"缺一个环境就能补上"。** 环境补上那天可能会发现它早就烂了。

⚠️ **所以 selfcheck 的 SKIP 一定要点名说缺什么**，不能静默略过。换台机器没装编译器 H2 还是会 SKIP —— **那时要当"状态未知"**。
