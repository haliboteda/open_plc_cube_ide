Type: task
Status: open

## Question

《生产测试指导文件 V0.1》里涉及软件的部分，**逐条给出「保留 / 改措辞 / 删掉 / 补充」的意见**，写成一份能直接发给编制人（王伦）的备忘。

## 已经确认要提的四条

| # | 文档原文位置 | 问题 | 建议 |
|---|---|---|---|
| 1 | 3.6「模式切换」 | 要板子**自己实时监测、异常自己点灯、自动计时、到点自动退出**老化模式 | **改**：老化由上位机计时与判定，异常时**上位机命令板子点灯**（`pt.led fault=1`）。板子只保留 `pt.hold` 看门狗做安全联锁。用户 2026-09-13 确认 |
| 2 | 3.6 / 3.10「Hutschienenverbinder 接口信号环回测试」 | 没有能插 J4 的陪测板；`PH13/PH14` 与控制口共用 UART4，测它要放弃控制台 | **删**（`DECISIONS.md` 35 + 39）。用户 2026-09-13：「没有陪测板，一切以板子整体测试为方案」 |
| 3 | 3.6 / 3.10 五个通信口 | 全写「**上传/下载文件，读取速率并判定**」。CAN/RS485/KNX 是总线，没有「文件」；KNX TP1 固定 9600 bps，速率不构成判据 | **改措辞**（已定，[DECISIONS.md 第 42 条](../../../design/DECISIONS.md)）：`eth`/`usb` 留速率；`can`/`rs485`/`knx` 改成**帧数 + 丢帧率 + 总线错误计数器归零** |
| 4 | 3.6 / 3.10「USB 通信测试」 | 写「向固定 USB 设备上传/下载文件」，但板子是 **Device**（文档自己在「关键观察」栏也写了 `USB为Device`） | **改措辞**：PC 才是主机 |

## 还要补进这份备忘的

- **[04](04-board-selfproof-matrix.md) 的三分表** —— 哪些板子自证、哪些是人工项、哪些不做。文档现在把人工项也写成了软件需求。
- **那五项板子拿不到数的**（待机功耗、最高功耗、3V3/5V/5V_EXT 电压、高边输出电流、继电器触点电流）要在文档里明确标成**人工测量**，否则产线会等一个永远不会出现的自动判定。
- **SN / 标签 / 过站 / 装箱**：文档已经把它列成独立的「系统管控软件」，建议在「功能测试软件」条目下明确**不含**这些，避免归属含糊。
