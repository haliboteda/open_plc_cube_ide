# 06 · 老化（工站 8）按「上位机监工」落地

Type: task
Status: open
Blocked by: 01

## Question

文档 3.8 老化要「循环执行 CPU/SDRAM 压力、Ethernet 数据、CAN/RS485 通信、DI 切换、高边负载和继电器周期动作」，并「监控板载温度、供电电流、复位原因、通信错误和输出故障」。**用现有的「持续测试」怎么落？**

## 用户 2026-09-13 定的

老化模式**不做成板子自治**。原话：**「我觉得完全可以上位机发现异常了，给板子让其亮灯」**。落成 `DECISIONS.md` 39 / 40 的配套。

## 对照：文档要的 vs 现在有的

| 文档要求 | 现状 | 差距 |
|---|---|---|
| 循环执行多端口压力 | ✅ 勾多个端口 + 「持续」+ 时长（1/2/3/4 小时 / 一直） | 无 |
| 系统自动计时、到点退出 | ✅ 上位机计时，到点发 `pt.stop` | 无 |
| 异常时指示灯提醒 | ✅ 上位机判出故障 → `pt.led fault=1`；`pt.hold` 到期板子自己点 | 无 |
| 完整日志上传 | ✅ 滚动日志 `runlogs/run-<时间戳>.log` | 无 |
| 监控**板载温度** | ✅ `temp` 会话 | 无 |
| 监控**供电电流** | ❌ | **板子无采样**（[00](00-scope-from-user.md)）。人工或从文档删 |
| 监控**复位原因** | ⚠️ bootloader 启动日志里有 `Reset cause`，**工装镜像里没有对应的帧字段** | 要补一个 `pt.run` 目标报复位原因 |
| 监控**通信错误** | ✅ CAN `tec/rec/lec`、RS485 `overrun`、各口 `miss` | 无 |
| 监控**输出故障** | ⚠️ AOUT 有 `AOUT1_EF`/`AOUT2_EF` 故障反馈脚（PI4/PE3）；高边开关的故障位**没有回到 MCU** | 要核实 AOUT_EF 是否已进帧 |
| 「异常复位/死机 0 次」判据 | ❌ | 挡在「复位原因」那一条上 |
| 45±5 °C 温箱 | ❌ 不在软件范围 | — |

## 要做的

1. **补 `pt.run reset.cause`**（或加进现有某个帧）——「异常复位/死机 0 次」是文档的硬判据，现在无从判起。
2. **核实 `AOUT1_EF` / `AOUT2_EF` 有没有进 `aout` 会话的帧**，没有就补。
3. 「供电电流」「温箱」两项在 [02](02-doc-review-memo.md) 的备忘里说明为什么不做。
