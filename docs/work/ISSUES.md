# P1 · 卡在别人身上或影响客户的

## ISS-B2 · 两块板的 MAC 是否互不相同

**等第二块板。**

| | |
|---|---|
| **是什么** | MAC 地址从芯片 UID 派生的算法 |
| **做什么用的** | 取代原先写死的 `00:80:E1:00:43:21` —— 那个值所有板子相同，同一网段放两台直接冲突 |
| **在哪找** | bootloader `LWIP/Target/ethernetif.c` 的 USER CODE MACADDRESS 块<br>core `core:libraries/OpenPLC_Net/src/ethernetif.c`（**跨仓镜像，改一处必须改另一处**） |
| **可能的影响** | 单板已验证：两侧串口都打印 `02:BB:49:3E:A8:02`，同 IP。但**"两块板不同"从未观察过** —— 如果派生算法有缺陷，量产时才会暴露成大面积 IP 冲突 |
| **要做什么** | 拿到第二块板，同网段同时上电，比对两边串口打印的 MAC（用例 **M3**） |

⚠️ **P2 已经自动比对了两侧派生算法的一致性**，剩下的只有"算法本身会不会撞"，那需要真的两块板。

⚠️ **产线要留 MAC 记录**，否则"不重复"无从判起 —— `$TOOL:TestCase/acceptance/checklist.md` 的 `CHK-C3`。检查单本身现在就能写，不用等板子。

## ISS-A3 · PG9 改输入应该挪到 `.ioc` 里

**用户已认领。攒够了一起烧，别为单条跑一趟 ST-Link。**

| | |
|---|---|
| **是什么** | `BOOT0_ConfigureAsInput()`，`Core/Src/gpio.c` 的 USER CODE 块，由 `main.c` 在 `MX_GPIO_Init()` 之后调用 |
| **做什么用的** | 把 CubeMX 生成的 PG9 推挽输出改回输入。理由和实测见 [../design/HARDWARE-FACTS.md](../design/HARDWARE-FACTS.md) |
| **为什么现在长这样** | 2026-08-18 那次是**受控实验**，只想动一个变量；重新生成整个工程会引入第二个变量 |
| **要做什么** | 在 `.ioc` 里把 PG9 设成 GPIO_Input，重新生成，然后**删掉 `BOOT0_ConfigureAsInput()` 和 main.c 里的调用** |
| **不做会怎样** | 🟢 功能上没影响 —— 它只是把已经配好的引脚再配一遍。但会变成"没人敢动的重复代码"，而且下一个人看到生成段仍写着 `OUTPUT_PP` 会困惑 |

⚠️ **`.ioc` 改完必须重新验一次 RESET 按钮和 BOOT0 长按** —— 重新生成会动整个 `MX_GPIO_Init()`，不只是这一个脚。

## ISS-C1 · 模拟校准值存在板子的哪里，还没定

用户 2026-09-10：**「校准值怎么保存下来，再说吧，记一个 todo。」** 所以这条是**挂起**，不是待办 —— 在定之前不写存储代码。

**为什么非定不可**：校准值是「这块板出厂时的物理事实」，**必须活过工装镜像被 bootloader + app 换掉**。工装整片烧，烧完这块板的校准值就得还在。

现在的 flash 分区见 [../../OpenPLC_Bootloader.md](../../OpenPLC_Bootloader.md)。当初摆的四条路（**已由下面 2026-09-14 那节取代，留作记录**）：

| | 放哪 | 代价 |
|---|---|---|
| A | bootloader 状态扇区（`0x081E0000`）里加一种记录 | 复用现成的 journal 机制；⚠️ **journal reclaim 会擦整个扇区**，校准值得跟着搬 |
| **B** | **单独切一个扇区**（如 bank2 sector 6 `0x081C0000`） | app 上限少 128K。⚠️ **要改的地址守卫只有一处，但就是挡在 app 上传和 bootloader 状态之间的那唯一一道**（`Core/Src/usbd_cdc_flash.c:226`） |
| C | STM32H7 的 OTP 区（1 KB，一次性） | 永不被擦；⚠️ **写死就不能重新校准** |
| D | RTC 备份寄存器 | 只有 128 字节，**掉备份电池就没了** |

**已经定了的一半**：值**不进** Arduino core 的源码。core 是一份构建发给所有人，塞不进每块板不同的数 —— 值住在板子上，core 加一个运行时读取的 API。这一条不需要再讨论。

**合格标准（是否通过、校准范围百分比）在上位机可配置**，用户 2026-09-10 定，所以那部分不受这条阻塞。

### ✅ 2026-09-13 解开了一半：先做「算」，「存」留在后面

用户原话：**「校正值存哪还没定，你先让上位机或板子谁先把校正值算出来」**。

**因此拆成两件，前一件不再被阻塞**：

| | 做什么 | 谁做 | 状态 |
|---|---|---|---|
| **算** | 多点采原始值 → 拟合出校准系数（零点 / 25% / 50% / 75% / 满量程） | **上位机** —— 第 22 / 38 条：计算和判定全在 PC，板子只报原始读数 | ✅ **可以开做** |
| **存** | 系数写回板子哪一块 flash | **上位机**（用户 2026-09-14） | **位置已定**，见下一节。代码还没写 |

算出来的系数**只显示在面板上**，不落盘也不写板子。这样校准链路能先跑通并验证拟合形状，**等存哪里定了再接写入那一段**。

### 2026-09-14：流程定了，只剩「放哪个扇区」

用户设想的流程，**已核实成立**：

1. 校准值算出来 —— **上位机算**（第 22 / 38 条），板子只报原始读数
2. **上位机把系数写进 flash** —— 用户原话：**「上位机软件来写校准值」**。所以**固件不加任何写入命令**，上位机经 JLINK 直接写那个扇区
3. 工站 10 重烧 bootloader + app 时，烧录工具**跳过那个扇区不编程它**，值原地不动

**这条流程干掉了原来那个要问产线的问题。**「工站 10 是不是 mass erase」不用再问 —— 那次烧录由我方的 JLINK CLI 包装发起（[DECISIONS.md 第 21 条](../design/DECISIONS.md)），擦法是我方的参数，不是产线给的既成事实。

#### 但「最后一个扇区」已经被占了

用户设想里写的是「flash 最后一个 section」。核实结果：`0x081E0000`-`0x081FFFFF`（bank2 sector 7，128K）**就是 bootloader 的 journal 扇区**（`IAP_STATE_SECTOR_ADDR`，`Core/Inc/usbd_cdc_flash.h:75`），整块是一个 append-only 日志，4096 个 32 字节槽。

工装写它没问题（工装镜像整片烧、顶掉 bootloader，那时扇区是空的），重烧时读它也没问题。**冲突发生在重烧之后** —— bootloader 一跑，journal 就从同一个地址开始追加。

#### 真正要躲的是 reclaim，不是重烧

| 敌人 | 什么时候 | 上面那条流程管用吗 |
|---|---|---|
| 工站 10 整片重烧 | 出厂前，一次 | ✅ 管用 —— 跳过那个扇区就行 |
| **客户日后的 IAP 升级** | 出厂后，每次 | ❌ **不管用**，那时没有烧录工具在场 |

`journal_reclaim()`（`IAPServer/bootloader_state.c`）在日志满时**擦整个扇区**，而扇区是擦除粒度，128K 一整块，没法只擦一半。一次成功升级吃 5 个槽，约 800 次升级触发一次 —— **那时校准值静默消失，没有任何东西会报警**。

#### 已定：最后一个扇区，bootloader 擦之前先搬走

用户 2026-09-14 原话：**「就是最后一个扇区，因为 boot 会在擦之前先把补偿值读出来，另行处理。」**

| | |
|---|---|
| **放哪** | `IAP_STATE_SECTOR_ADDR`（`0x081E0000`）那个扇区**的最后 8 个槽** |
| **谁写** | 上位机，经 JLINK |
| **谁保它活着** | **bootloader 自己** —— `journal_reclaim()` 擦之前把这 8 个槽读进 RAM，擦完写回 |
| **app 上限** | **不变，1792K** |
| **擦除守卫** | **不动**（`Core/Src/usbd_cdc_flash.c:226` 挡的仍是整个状态扇区） |

**为什么是 8 个槽而不是一个固定位置**：STM32H7 的 flash word 写过一次就不能再写（`IAPServer/bootloader_state.h:42`）。重新校准要能覆盖旧值，所以这一小块也得是 append —— **最新的非空槽生效**；8 个用完了由 reclaim 压回第一个。

**上位机要知道的只有三件事**：起始地址、结构体、「找第一个空槽写」。**它不用懂 journal 的记录格式**，所以这不构成新的跨仓镜像项。

⚠️ **这些代码 AI 不写。** 用户 2026-09-14 重申：**「校准码代码不用写，你就写个 todo 就行，后面我会处理。」** 下面这张表是 TODO，不是排期。
