# 总表：要做什么、做到哪、什么在挡路

**这是唯一一张需求和测试合并的表。** 建于 2026-08-22，合并了原来的 `REQUIREMENTS.md`（要什么）和 `TEST-PLAN.md`（怎么证明）—— 它们本来是同一件事的两半，分开放的结果是同一个数字在两边写成两个值。

**怎么用这份文件：**

| 你想知道 | 看哪一节 |
|---|---|
| 今天能干什么，什么在挡路 | [一、全局](#一全局一眼看完) —— 12 行，一眼看完 |
| 哪些测试必须做，先做哪个 | [二、优先级](#二必须做的测试按优先级) |
| 某条需求到哪一步了 | [三、明细](#三明细54-条按模块分组) —— 54 行，按模块分组 |
| 某个用例怎么跑、判据是什么 | `$TOOL/TestTool/TEST-CASES.md`（**跨仓，贴着代码走**） |
| 某个数字的出处 | [test/MEASUREMENTS.md](test/MEASUREMENTS.md) —— **所有实测数字的唯一出处** |
| 某个编号是什么 | [ID-MAP.md](ID-MAP.md) |

**状态符号（六个）：**

| 符号 | 含义 |
|---|---|
| ✅ | 已实现**且**有实测证据，**且证据仍然成立** |
| ⚠️ | 曾经通过，但**证据已经失效**（系统变了 / 硬件变了），要重跑 |
| 🟡 | 已实现，但**没有测试能证明**它（或只测过一半） |
| ❌ | **测了，不过** |
| ⬜ | 未做 |
| ⛔ | 明确不做 |

> ⚠️ **🟡 和 ⚠️ 才是这张表最有用的部分。** ✅ 和 ⬜ 都不会骗人；🟡 会（功能在跑，没人测，改坏了也没人知道），⚠️ 更会（旁边挂着一个真实的通过记录，看起来和 ✅ 一模一样）。
>
> **「证据还成立吗」这一列是 2026-08-22 新加的**，因为 [test/COVERAGE-GAPS.md](test/COVERAGE-GAPS.md) 自己承认"没有东西检查文档里的结论是否已过期" —— 而当天就查出三条过期的 ✅。

## 四、维护这张表

- **状态列变化时就地改，别开新表。** 2026-08-22 之前状态在 5 个文件里各写一遍，结果是同一条需求三个不同的值。
- **✅ 必须能指向证据，而且证据必须带日期。** 指不出来的就是 🟡，**宁可难看也别骗人**。
- **⚠️ 是给"系统变了"用的。** 一条曾经真的通过、但前提已经不成立的 ✅，比 ⬜ 危险得多 —— 它旁边挂着一个真实的通过记录。判断标准只有一句：**今天重跑一次，还会过吗？**
- **失败也要填。** 只记通过的表等于没有表。
- **新需求加在对应模块末尾，编号只增不改**（用例和代码引用的是编号）。
- **每条 ✅ 的用例号必须能在 `$TOOL/TestTool/TEST-CASES.md` 里找到同名条目**，反过来也一样。这个对照该脚本化 —— 见 [test/COVERAGE-GAPS.md](test/COVERAGE-GAPS.md)。
